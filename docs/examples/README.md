# Worked Examples

These examples run real problems through Grandmaster Mode and end in a
`🏁 Meta-Lesson`.

Each example should show how an observation becomes a pattern, abstraction,
primitive, or transfer lesson that improves future modeling.

## Observation record

Every worked example must label each observation as **empirical**, **reported**,
**synthetic**, or **illustrative**. The label identifies how the observation
relates to the phenomenon; it is not a quality score. Do not present reported
material as direct observation or use synthetic or illustrative material as if
it independently establishes a real-world occurrence.

Alongside the label, include the observation's provenance and its limits:

- observation context;
- collection method;
- temporal scope;
- observer or custodian;
- known limitations, including provenance gaps;
- contradictory evidence, or `None identified` if none is known; and
- confidence and the basis for it.

Use `Unknown` for missing provenance rather than filling gaps by inference. These
fields are the minimum record: examples may add detail when it helps a reader
assess the observation.

## Authoring closure across examples

A later example may claim closure for an earlier analysis only when it links to
that prior analysis and evaluates its predicted modeling improvement against a
later observation. Include the non-executable closure record defined in
[Grandmaster Mode](../grandmaster-mode.md#closure-check), including contradictory
results, the confidence update, and a supported, weakened, contradicted, or
inconclusive disposition.

Writing a `🏁 Meta-Lesson` does not by itself establish closure. A meta-lesson
states an abstraction; closure requires a later, linked comparison that assesses
whether the earlier analysis improved subsequent modeling.
