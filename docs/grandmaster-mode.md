# MindShift Grandmaster Mode

Grandmaster Mode is an analysis method for extracting transferable lessons from
observations. It supports the canonical research sequence:

```text
Observation → Pattern → Abstraction → Primitive → Transfer
```

The aim is to improve future modeling, not to create execution plans or govern
actions.

## Stage 1 — Surface Observation

**Identify:** patterns, biases, anomalies, friction points, recurring structures.

**Ask:**

- What pattern keeps repeating?
- What assumption may be distorting clarity?

## Stage 2 — Define Purpose

**Determine:** the actual question, the intended modeling improvement, and the
level of learning involved.

**Ask:**

- What problem is actually being studied?
- What level of learning is present?

## Stage 3 — Candidate Abstractions

**Identify:** candidate abstractions or distinctions that compress the observed
pattern.

**Ask:**

- What abstraction emerges from the observation?
- What would make it reusable beyond this case?

## Stage 4 — Transfer Analysis

**Evaluate:** where the abstraction transfers, where it fails, and how it improves
future modeling.

**Select:** the smallest useful abstraction or distinction.

## Output Format

The four-part output format below is **mandatory** for a Grandmaster Mode
analysis. Each analysis must include all four headings; the format is not merely
illustrative. Additional sections are allowed when they add useful evidence or
reasoning, but each extension must explicitly identify the canonical section it
supports so that the four-part output remains complete and recognizable.

```text
♟️ Position Summary
♜ Candidate Abstractions
🧠 Transfer Analysis
🏁 Meta-Lesson
```

## Closure Check

Before Stage 1 of a new analysis, verify whether the previous analysis improved
future modeling. Fold that result into the current observation.

Without this check, the method produces insight without testing transfer.

Record the check as a **non-executable closure record**. It is a human-readable
account of the comparison, not a schema, gate, instruction, or trigger for any
action. Include:

- **Prior analysis identity:** the title and link, or another stable citation,
  for the analysis being evaluated.
- **Predicted modeling improvement:** the specific improvement that the prior
  analysis expected to appear in later modeling.
- **Later observation:** the subsequent evidence used to assess that prediction,
  with its context and provenance.
- **Comparison outcome:** where the later observation matches, partly matches,
  or fails to match the prediction.
- **Contradictory result:** evidence that conflicts with the prediction, or
  `None identified` when none is known.
- **Confidence update:** the resulting change in confidence and the reason for
  that change.
- **Disposition:** one of the descriptive conclusions below.

Use **supported** when the later observation is consistent with the predicted
improvement, **weakened** when support is materially reduced but the prediction
is not overturned, **contradicted** when the later observation conflicts with
the prediction, and **inconclusive** when the available observation cannot
distinguish among those outcomes. These dispositions summarize analytical
comparison only. They do not approve work, govern execution, or initiate a next
step.
